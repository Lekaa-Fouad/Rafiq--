## 2. Standard Response Envelope

All REST endpoints (except `/health`, TTS binary, OCR-to-voice binary) return:

```json
{
  "success": true,
  "data": { ... },
  "message": "Human-readable status for logs.",
  "spoken_message": "What to read aloud to the user."
}
```

On error, `success=false`, `data=null`, and `spoken_message` has a user-facing error.

## 3. API Endpoints

### 3.1 Health — `GET /health` (no auth)

```
GET /health
→ 200 { success, data: { status, redis_connected, whisper_loaded }, message, spoken_message }
```

### 3.2 Voice — `POST /voice/stt`

**Purpose:** Speech-to-Text — transcribe uploaded audio via Faster-Whisper.

```
POST /voice/stt
Header: X-API-Key: 123
Content-Type: multipart/form-data

Fields:
  audio     (file, required)  — any audio file: wav, mp3, m4a, ogg, flac
  language  (text, optional)  — 'ar' or 'en'; omit for auto-detect

Response 200 (JSON):
{
  "success": true,
  "data": {
    "transcript": "Hello world",
    "language": "en",
    "confidence": 0.95,
    "duration_seconds": 3.2
  },
  "message": "Audio transcribed successfully.",
  "spoken_message": "Hello world"
}

Errors: 401 (bad key), 422 (empty/corrupt audio), 503 (Whisper not loaded)
```

### 3.3 Voice — `POST /voice/tts`

**Purpose:** Text-to-Speech — returns raw MP3 bytes (not JSON).

```
POST /voice/tts
Header: X-API-Key: 123
Content-Type: multipart/form-data

Fields:
  text      (text, required, max 2000 chars)
  voice     (text, optional) — e.g. 'en-US-JennyNeural', 'ar-SA-ZariyahNeural'
  rate      (text, optional) — e.g. '+10%', '-20%'
  language  (text, optional) — 'ar' or 'en' (auto-detected if omitted)

Response 200:
  Content-Type: audio/mpeg
  Content-Disposition: attachment; filename="speech.mp3"
  X-Voice-Used: en-US-JennyNeural
  X-Audio-Size: <bytes>
  Body: raw MP3 bytes

→ Play the response bytes directly using expo-av / expo-audio Sound API.
```

```
    "name": "Alice",
    "message": "..."
  },

}
```

### 3.5 Face — `POST /face/identify`

**Purpose:** Identify who is in a photo.

```
POST /face/identify
Header: X-API-Key: 123
Content-Type: multipart/form-data

Fields:
  image  (file, required) — portrait photo to identify

Response 200:
{
  "success": true,
  "data": {
    "identified": true,
    "name": "Alice",        // null if not recognized
    "confidence": 0.87,
    "face_id": "uuid",      // null if not recognized
    "distance": 0.13        // cosine distance; ≤ 0.40 = match
  },
  "spoken_message": "Face identification completed."
}
```

## 4. Running Backend + Mobile App Together (Local Dev)

### Backend
```bash
cd "h:\main gaduation project\Rafiq--\backend"
python -m venv venv && venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

### Mobile App (Expo)
```bash
cd "h:\main gaduation project\Rafiq--\mobile app"
npm install
npx expo start
```

### Environment variable for LAN testing (physical device)
In `mobile app/.env`:
```
EXPO_PUBLIC_API_URL=http://192.168.1.X:8000   # replace with your PC's LAN IP
EXPO_PUBLIC_API_KEY=123
```

Find your LAN IP: `ipconfig` → look for "IPv4 Address" under Wi-Fi adapter.

> The backend binds to `0.0.0.0:8000` when run with `uvicorn main:app --reload --port 8000`,
> so it is reachable from any device on the same LAN.
